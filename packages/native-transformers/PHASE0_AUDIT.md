# Phase 0 Audit – Babel to SWC parity

This document captures the baseline behaviours, module layout, and state that the native Rust transformers must reproduce byte-for-byte. It mirrors the TypeScript sources in `packages/babel-plugin` and `packages/babel-plugin-strip-runtime` so we can track parity work for the Rust crates in `packages/native-transformers/`.

## `@compiled/babel-plugin`

### Public entry points
- `src/index.ts` re-exports the default plugin from `babel-plugin.ts` and the TS types used by callers (`PluginOptions`, `Metadata`, `Resolver`, `State`, `Tag`, `TransformResult`).
- Consumers expect a Babel plugin function and the metadata tuple returned via `transform` helpers in tests (see `src/test-utils.ts`). The SWC port must keep the same callable surface and metadata shape.

### Plugin options (and defaults inferred from `babel-plugin.ts`)
- `cache`: `true | false | "file-pass"` (defaults to `true` in `Cache.initialize`).
- `importReact`: defaults to `true` unless `pragma.jsx` is active.
- `nonce`: optional string for inline style tags.
- `importSources`: merged with `DEFAULT_IMPORT_SOURCES` and normalized relative to the current cwd.
- `onIncludedFiles(files: string[])`: invoked on `Program.exit` if any files were evaluated; the SWC version must dedupe (`unique`) before calling.
- `optimizeCss`: toggles PostCSS normalization plugins; default observed in `packages/css/src/transform.ts` (`normalizeCSS`).
- `resolver`: either an object implementing `{ resolveSync(context, request) }` or a module path resolved relative to plugin `root` (via `require.resolve`).
- `extensions`: optional override for code traversal (defaults: `DEFAULT_CODE_EXTENSIONS = ['.js', '.jsx', '.ts', '.tsx']`).
- `parserBabelPlugins`: forwarded to `@babel/parser` when statically evaluating modules.
- `addComponentName`: toggles non-prod class name decoration for `styled`.
- `classNameCompressionMap`: map from full atomic class to compressed name; influences selector substitution in `atomicify-rules`.
- `processXcss`: defaults to `true`; gates `visitXcssPropPath`.
- `increaseSpecificity`: optional PostCSS plugin toggle.
- `sortAtRules`: toggles ordering in `sortAtomicStyleSheet`.
- `classHashPrefix`: prepended to the string hashed for the group component of atomic class names.
- `flattenMultipleSelectors`: defaults to `true`; disables the `flatten-multiple-selectors` + `discardDuplicates` stage when `false`.

### Plugin pass state (`types.ts`)
- `compiledImports`: per-file API usage toggle (`styled`, `ClassNames`, `css`, `keyframes`, `cssMap`).
- `usesXcss`: flips to `true` when `xcss` prop visitors run.
- `importedCompiledImports`: tracks runtime helper imports to avoid duplication.
- `importSources`: normalized module origins enabling the transform.
- `pragma`: flags derived from JSX pragmas.
- `pathsToCleanup`: array of `{ action: 'replace' | 'remove'; path: NodePath }` to execute on `Program.exit`.
- `opts`: snapshot of `PluginOptions`.
- `file`: Babel file object (needed for metadata and filename access).
- `sheets`: hoisted style binding registry.
- `cache`: LRU cache (`utils/cache.ts`) keyed by hashed namespace+cacheKey.
- `includedFiles`: absolute paths added during static evaluation; triggers `onIncludedFiles` callback.
- `cssMap`: memoises compiled stylesheets per `cssMap()` call.
- `ignoreMemberExpressions`: map of AST nodes to skip (set in visitors).
- `resolver`: `Resolver` object chosen during `pre()`.
- `transformCache`: `WeakMap<NodePath, true>` preventing double transforms.

### Top-level visitor flow (`babel-plugin.ts`)
- `pre`: resets caches (`sheets`, `cssMap`, `ignoreMemberExpressions`, `transformCache`), configures `Cache`, resolves custom resolver, normalizes `importSources`, primes `includedFiles` and `pragma` state.
- `Program.enter`: strips JSX pragmas, toggles runtime detection, and, when necessary, removes JSX pragma comments.
- `Program.exit`:
  - Ensures React/forwardRef imports when needed.
  - Adds `/* filename generated by ... */` banner comment followed by `noop()` to mimic Babel output structure.
  - Calls `onIncludedFiles(unique(includedFiles))`.
  - Executes queued `pathsToCleanup` mutations (remove or replace with `null`).
- `ImportDeclaration`: detects Compiled imports, records enabled APIs, removes the specifiers entirely once transformed.
- `TaggedTemplateExpression|CallExpression`: dispatches to the appropriate visitor (`visitCssMapPath`, `visitStyledPath`), performs `normalizePropsUsage`, and schedules util calls for cleanup.
- `JSXElement`: handles `<ClassNames>` only when the API was imported.
- `JSXOpeningElement`: applies `css` prop (`visitCssPropPath`) and optional `xcss` transform (`visitXcssPropPath`).

### Module layout parity requirements
Each TS module already has a corresponding Rust stub under `packages/native-transformers/compiled_babel/src/...` mirroring the relative path. Key responsibilities:
- `class-names/index.ts`: converts `<ClassNames>` render prop usage into runtime calls, collects CSS via `buildCss` and `transformCssItems`.
- `css-map/index.ts` + `process-selectors.ts`: evaluates `cssMap()` calls, hoists generated maps, and feeds sheets into state caches.
- `css-prop/index.ts`: rewrites JSX `css` props into runtime style props, integrates with `buildCss`/`transformCssItems`.
- `styled/index.ts`: transforms `styled` tagged templates / call expressions, handles component wrapping and props hoisting.
- `xcss-prop/index.ts`: transforms `xcss` prop usages (gateable via `processXcss`).
- `utils/*`: shared helpers for AST manipulation, static evaluation (`evaluate-expression.ts` + `traverse-expression/*`), caching, runtime import management, metadata tracking, and CSS pipeline bridging (`transform-css-items.ts` -> `@compiled/css`’s `transformCss`).
- `constants.ts` & `types.ts`: constants for generated identifier names and shared metadata types.

### Static evaluation and resolver behaviour
- `utils/resolve-binding.ts` uses `@babel/parser` with `DEFAULT_PARSER_BABEL_PLUGINS` and `resolve.sync` to locate modules when no custom resolver is provided.
- When `resolver` option is present, `resolver.resolveSync(filename, request)` must be called with the current file path and import specifier.
- Evaluated modules respect `DEFAULT_CODE_EXTENSIONS` and the caller’s `extensions` override.
- `Cache` class (LRU) ensures repeated evaluations reuse results unless caching disabled.

### CSS pipeline coupling
- `utils/transform-css-items.ts` wraps `@compiled/css`’s `transformCss` to produce `{ sheets, classNames }` while threading metadata for hashing and evaluation errors.
- `build-css-variables.ts`, `build-compiled-component.ts`, `build-styled-component.ts`, and related utilities craft runtime AST nodes that consume the generated sheets.
- Hashing invariants stem from `packages/css/src/plugins/atomicify-rules.ts`: atomic class names take the form `_{group}{value}`, where `group = hash(prefix + atRule + selectors + property).slice(0, 4)` and `value = hash(value + important?).slice(0, 4)`. The Rust port must reproduce this algorithm byte-for-byte (including the `hash` helper and selector normalization rules).

## `@compiled/babel-plugin-strip-runtime`

### Public entry
- `src/index.ts` exports the Babel plugin via `declare<PluginPass>`. Types re-exported from `src/index.ts` for consumers (`PluginPass`, `PluginOptions`, `BabelFileMetadata`).

### Plugin options
- `styleSheetPath`: when provided, each atomic rule triggers `require("${styleSheetPath}?style=${encodeURIComponent(rule)}")` injection.
- `compiledRequireExclude`: suppresses import injection and instead pushes rules into `file.metadata.styleRules` (for SSR tooling).
- `extractStylesToDirectory`: `{ source, dest }` pair enabling CSS file emission alongside transformed module.
- `sortAtRules` / `sortShorthand`: forwarded to `@compiled/css`’s `sort` helper when writing extracted CSS.

### Plugin pass state
- `styleRules: string[]`: aggregated at transform time; initialised in `pre()`.
- `classicJsxPragmaName` & `jsxPragmaIsCompiled`: track JSX pragma metadata for compatibility with the runtime removal logic.
- `file`: Babel file reference whose metadata collects `styleRules` when `compiledRequireExclude` is set.

### Visitor responsibilities
- `Program.exit`:
  - Validates filename presence.
  - When `compiledRequireExclude` is true, appends `styleRules` into `file.metadata.styleRules` instead of mutating AST.
  - When `styleSheetPath` is provided, injects `require()` calls per rule (deduplication handled elsewhere) preserving comment order via `preserveLeadingComments`.
  - When `extractStylesToDirectory` is set, emits `.compiled.css` files to `dest`, sorts their contents with `@compiled/css.sort` using `sortAtRules`/`sortShorthand`, and inserts a sidecar `import './<name>.compiled.css'` at the top of the module.
- `ImportSpecifier`: strips `CC`/`CS` named imports from `@compiled/react` runtime.
- `JSXElement`: replaces `<CC>{(_, compiledStyles, _, child)}</CC>` with the user land child expression after removing inline style declarations from the companion `<CS>` call (`utils/remove-style-declarations.ts`).
- `CallExpression`: handles classic React runtime (`React.createElement`) and automatic runtime (`_jsxs`) cases, removing runtime wrappers and hoisting style rules.

### Utility modules
- `utils/remove-style-declarations.ts`: inspects `CS` call expressions, removes `style` declarations, and pushes serialized CSS into `styleRules`.
- `utils/is-automatic-runtime.ts`, `is-create-element.ts`, `is-cc-component.ts`: runtime detection helpers.
- `utils/to-uri-component.ts`: matches Parcel transformer behaviour by serializing rule text.

## `@compiled/css` pipeline requirements for `postcss.rs`

To preserve hashing and sheet emission, the Rust pipeline must match the TypeScript implementation exactly:

1. Run (in order) within `transformCss` (`packages/css/src/transform.ts`):
   - `discardDuplicates`
   - `discardEmptyRules`
   - `parentOrphanedPseudos`
   - `postcss-nested` with the custom `bubble`/`unwrap` config
   - `normalizeCSS(opts)` (conditionally adds cssnano plugins based on `optimizeCss`)
   - `expandShorthands`
   - `atomicifyRules` (captures class names, honours `classNameCompressionMap`, `classHashPrefix`)
   - Optionally `flattenMultipleSelectors` + `discardDuplicates`
   - Optionally `increaseSpecificity`
   - `sortAtomicStyleSheet` with `sortAtRules`/`sortShorthand`
   - Conditional `autoprefixer()` (skipped when `process.env.AUTOPREFIXER === 'off'`)
   - `postcss-normalize-whitespace`
   - `extractStyleSheets`
2. `sort.ts` runs `postcss-discard-duplicates`, `mergeDuplicateAtRules`, and `sortAtomicStyleSheet` with optional flags.
3. Hashing uses `@compiled/utils/hash` and must keep the same 4-character slicing and selector normalization rules (see `atomicify-rules.ts`).

## File/folder parity checkpoints
- Rust crates already contain 1:1 stub modules (paths mirror TS sources). This audit confirms the mapping so future phases can replace the stubs with implementations without renaming files.
- Additional directories required by the plan (fixtures harness with `in.jsx`, `babel-out.js`, `swc-style-rules.json`, etc.) will be introduced during verification phases.
